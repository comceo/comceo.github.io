# codex积分点数购买流程及收费标准

Codex的额度提示弹出来那一刻，大多数人的第一反应是"要不要升 Pro"。但在掏钱之前，有件事比选套餐更重要：搞清楚你缺的是"这一次的缺口"，还是"长期的结构性缺口"。这两种情况，最省钱的处理方式完全相反。下面这套判断清单，是我在 <https://meeke.github.io> 的代充商城里反复下单之后攒出来的，一共四步，走完再决定买什么，能少花不少冤枉钱。

## 一、先分清三种"不够用"

**情形 A：偶发撞上限。** 一周摊不上一次，撞上了也是手头正好有个大批量任务。这种等五小时窗口重置就行，零成本，一分钱不用花。

**情形 B：周期性不够。** 每个计费周期的中段就见底了，剩下的时间靠等重置熬过去，但还没到"天天撞"的程度。这是加购点数的典型场景。

**情形 C：结构性不够。** 窗口一开就烧完，一天撞好几次，任务排着队等额度。这种该升套餐，点数只是止血，治不了根。

判断方法很简单：翻最近两周的用量记录，看撞上限的频率，以及它发生在周期的第几天。如果集中在中后段，是 A 或 B；如果一开窗就撞，基本就是 C。

## 二、算一笔很简单的账

只需要两个数：

- **每点成本** = 一份点数的价格 ÷ 该份包含的点数
- **升级的边际成本** = 目标套餐价 − 当前套餐价，再除以新增的额度

把这两个"每单位额度的价格"摆在一起比，哪个低走哪个。听起来简单，但有三个细节会让人算错：

第一，套餐是按周期固定扣费，点数是一次性买断。如果一个月只缺两三次，包月的那部分额度大部分时间是躺在那里睡觉的，这时候买点数更划算。

第二，**扣费顺序是先套餐、后点数**。所以买了点数不代表当月可以不看套餐——它只是撞线之后的一块缓冲垫。指望"充了 500 点就不用管套餐了"，属于误会。

第三，点数和 API 余额是两套计费体系，互不抵扣。有人以为充的点数能拿去跑 API 脚本，不行。

## 三、什么情况适合走代充商城

对号入座一下：

- 手上的卡在官方付款页刷不过去；
- 只想补一份额度，不想动现有套餐；
- 活就在眼前，需要几十分钟内到账。

反过来，如果你想要的是更强的模型、更高的并发、或者某些套餐专属的能力，那是档位问题，充点数解决不了，别在下单页反复确认"是不是买错了"。

## 四、下单前必须核对的三件事

**第一，账号当前状态。** 是 Free 还是 Plus / Pro，还剩多久到期。Free 状态的账号通常不能单独充点数，得先把套餐开起来；套餐快要到期的，建议先续费再充，避免两个操作叠在一起把账算乱。

**第二，收卡商的邮箱。** 这是全程唯一能拿到卡密的地方，填错等于把东西送给了别人。手机上下单尤其容易手滑，一个字一个字核。

**第三，份数。** 按第二节算出来的缺口买。第一次接触的人容易犯两个极端：要么只买一份不够用，要么一次囤十份压在那里。先买够一个周期的量，跑一轮再补。

## 五、四个被问得最多的误区

**"点数会过期吗？"**  
跟着账号套餐走，具体以官方说明为准。结论是别囤，按需买。

**"买了点数，五小时窗口还重置吗？"**  
重置。重置之后先扣套餐额度，套餐额度用尽才轮到点数余额，两者不冲突。

**"明显更便宜的那家能不能买？"**  
单价显著低于市场价的，多半不是充进你自己账号，而是共享号或成品号。看着省钱，用起来是另一回事，账号安全和售后都要自己扛。

**"先付款再问客服行不行？"**  
账号有异常状态（到期、登录不上、欠费）的时候，先聊再付。付完才发现充不进去，退款流程比咨询慢得多。
